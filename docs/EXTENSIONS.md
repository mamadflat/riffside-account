# قرارداد مکمل‌های پنل — API 1 / پنل 0.6.0

پنل پایه برای همهٔ سایت‌ها یک کد و یک انتشار دارد. کد اختصاصی هر پروژه در افزونه و مخزن جدا نگهداری می‌شود؛ تشخیص دامنه و شرط نام مشتری در هسته ممنوع است. برای مشتری عمومی فقط پنل پایه و افزونه‌های عمومی مورد نیاز نصب می‌شوند. باشگاه همچنان مالک امتیازها و قوانین پاداش است.

## اتصال

مکمل در header به `woocommerce, riffside-account` وابسته است. پس از `plugins_loaded` با اولویت 40، وجود `Riffside\Account\Extensions`، نسخهٔ پنل حداقل 0.6.0 و `Extensions::API_VERSION === 1` را بررسی کند. نبود یا قدیمی بودن پنل باید فقط اعلان مدیریت بسازد؛ کد اجرایی مکمل ثبت نشود.

```php
add_action('riffside_account_register_extensions', function ($api) {
    if ($api !== 1) return;
    \Riffside\Account\Extensions::register('page', 'ra-example-history', [
        'title' => 'سوابق من',
        'icon' => 'files',
        'priority' => 50,
        'enabled' => true,
        'permission' => static fn($user_id, $context) => current_user_can('read'),
        'render' => static function ($user_id, $context) {
            echo '<p>' . esc_html('اطلاعات همین مشتری را از منبع پروژه بخوانید.') . '</p>';
        },
    ]);
});
```

شناسهٔ هر امکان باید `ra-{project}-{feature}` و مطابق `^ra-[a-z][a-z0-9-]{2,45}$` باشد. شناسهٔ تکراری، مسیر رزروشده، برخورد با alias یک مسیر ووکامرس، renderer نامعتبر و مقدار مبهم enabled رد می‌شود؛ `register()` مقدار boolean برمی‌گرداند. ثبت فقط در رویداد معرفی مکمل انجام شود؛ رجیستری هر درخواست مستقل است.

| kind | محل نمایش | context | کنترل دسترسی هسته |
|---|---|---|---|
| `page` | صفحهٔ حساب و منوی آن | null | ورود، enabled و permission؛ مسیر مستقیم غیرمجاز 404 |
| `widget` | بعد از ویجت‌های پایهٔ داشبورد | null | ورود، enabled و permission |
| `order` | جزئیات سفارش | شیء WC_Order | مالکیت سفارش پیش از اجرای permission و renderer |
| `settings` | پایین فرم تنظیمات پنل | null | manage_woocommerce، enabled و permission |

پارامتر اول renderer همیشه شناسهٔ کاربر نشست است، نه مقدار URL یا فرم. renderer کد PHP مورد اعتماد افزونه است و مسئول escape کردن خروجی، محدودکردن query به همان مشتری، nonce و capability هر عملیات نوشتن خودش است. هسته فقط عنوان و قاب را escape می‌کند. اطلاعات مشتریان نباید در گزینهٔ مشترک، کش عمومی یا ویجت مهمان ذخیره شود.

ترتیب مکمل‌ها با priority است. منوی خروج در انتها می‌ماند. مسیرهای غیرفعال ثبت می‌مانند تا دسترسی مستقیم مسدود شود. تغییر مجموعهٔ مسیرها فقط در درخواست مدیر مجاز باعث flush نرم rewrite می‌شود، نه در بازدید مشتری. هنگام فعال/غیرفعال‌سازی مکمل می‌توان گزینهٔ `riffside_account_extension_routes` را حذف کرد؛ درخواست بعدی مدیریت آن را بازسازی می‌کند.

## ظاهر و تنظیمات

- فیلتر `riffside_account_appearance_presets` پالت پروژه را اضافه می‌کند. پالت پایهٔ `riffside` قابل حذف یا جایگزینی توسط این فیلتر نیست. ساختار پالت از `assets/presets.json` الگو گرفته شود.
- فیلتر `riffside_account_appearance_css($css, $settings)` برای CSS محدود به `.riffside-account` است. ورودی دلخواه مشتری را به CSS خام تبدیل نکنید.
- مکمل از کلاس‌ها، متغیرهای `--ra-*`، فونت میزبان و امکانات کپی پنل استفاده کند؛ CSS عمومی قالب را بازنویسی نکند.
- مکمل Settings API، گروه nonce، گزینهٔ namespaced و sanitize مستقل داشته باشد. `settings` renderer بیرون فرم هسته قرار دارد و می‌تواند فرم مستقل بسازد. برای ذخیره با manage_woocommerce، فیلتر `option_page_capability_{group}` هم تنظیم شود.
- فعال‌سازی مکمل نباید تنظیمات هسته یا باشگاه را overwrite کند. تغییر نام preset به‌تنهایی رنگ‌های ذخیره‌شده را پاک نمی‌کند. حذف مکمل باید دادهٔ سفارش و امتیاز را حفظ کند.

## نسخه‌بندی و انتشار

هر مکمل مخزن خصوصی، tag، changelog و ZIP جدا دارد. در ZIP عمومی پنل، preset، آداپتر قالب یا کلید متادیتای اختصاصی پروژه قرار نمی‌گیرد. قرارداد API 1 باید در نسخه‌های سازگار پنل حفظ شود؛ تغییر مخرب به API جدید و برنامهٔ ارتقای مکمل‌ها نیاز دارد. آپدیت خصوصی خودکار مکمل‌ها در این مرحله پیاده‌سازی نشده؛ ZIP مستقل نصب می‌شود.

ماتریس آزمون هر انتشار: پنل تنها؛ پنل و باشگاه؛ پنل و هر مکمل؛ خاموش/روشن‌شدن مکمل و ویژگی؛ نبود/قدیمی بودن پنل؛ ورود مهمان؛ دسترسی به سفارش مشتری دیگر؛ حفظ تنظیمات/داده‌ها؛ رابط RTL موبایل. مسیرهای توسعه با `php tests/extensions.php` و آزمون‌های فعلی پنل بررسی می‌شوند.
