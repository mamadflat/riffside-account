# قرارداد اتصال — نسخهٔ ۱

دو بستهٔ وردپرس: `riffside-account` و `customer-club`. هیچ‌کدام فایل‌های دیگری را در بستهٔ خود ندارد. منبع مشترک: [riffside-design-system](https://github.com/mamadflat/riffside-design-system).

## قرارداد پیاده‌شده در Panel 0.3.0 / Club 2.6.1

هر بسته `assets/shared/riffside-ui/manifest.json` با نسخهٔ 1.0.0، contract برابر 1 و SHA-256 دارایی‌ها دارد. handle مشترک `riffside-ui-v1` فقط یک بار ثبت و بارگذاری می‌شود. هر افزونه کپی خودکفای همین پایه را دارد؛ با غیرفعال‌شدن یکی، دیگری CSS خود را بارگذاری می‌کند. توکن‌های نسخهٔ اصلی جدید باید scope و handle جدید داشته باشند؛ تغییر مخرب زیر handle v1 ممنوع است.

پنل، فیلتر `customer_club_appearance_settings` را فقط برای حساب واردشده و خارج از ادمین اعمال می‌کند: theme، mode، default_mode و palettes. باشگاه خروجی را sanitize می‌کند. خواندن نمایش هیچ option یا تراکنش مالی را نمی‌نویسد. فیلتر `customer_club_account_embedded` از اعمال قاب عمومی باشگاه روی body پنل جلوگیری می‌کند.

در حالت جاسازی‌شده، کنترل تم باشگاه مخفی است، ترجیح مرورگر `riffside-account-mode` استفاده می‌شود و رویداد `riffside:appearance` حالت را همگام می‌کند. در حالت مستقل کلید `customer-club-color-mode` و کنترل خود باشگاه معتبرند. سیاست اجباری روشن/تیرهٔ مدیر همیشه مقدم است.

پنل موجودی را از `Customer_Club\Points_Ledger::balance()` و عنوان واحد را از `Customer_Club\Coin::name()` می‌خواند. پنل هیچ پاداشی ثبت نمی‌کند. API نسخه‌دار ویجت‌ها، مأموریت‌ها و گزارش دعوت‌ها هنوز برنامهٔ آینده است؛ رابط فعلی را با API آینده اشتباه نگیرید.

## سازگاری و آزمون انتشار

| ترکیب | رفتار مورد انتظار |
|---|---|
| پنل جدید + باشگاه جدید | رنگ، فونت میزبان، فاصله و کنترل تم هماهنگ؛ یک قاب حساب |
| پنل فعال، باشگاه غیرفعال | سفارش و پروفایل کار می‌کنند؛ موجودی جعلی و لینک باشگاه نمایش داده نمی‌شود |
| باشگاه فعال، پنل غیرفعال | نمایش مستقل باشگاه با تنظیمات ذخیره‌شدهٔ خودش |
| پنل جدید + باشگاه 2.6.0 | موجودی و endpointهای قبلی کار می‌کنند؛ همگامی کامل ظاهر نیازمند 2.6.1+ است |
| پنل 0.2.0 + باشگاه جدید | هر افزونه تنظیمات خودش را دارد؛ داده و endpointها باید حفظ شوند |

پیش از انتشار: تست PHP/JS، اعتبارسنجی hash دارایی مشترک، حساب مهمان/مشتری، موبایل، هر افزونه به‌تنهایی و کنار هم، حالت اجباری/انتخابی تم، حفظ تنظیمات و دفتر تراکنش‌ها بررسی شود. نبود یک افزونه نباید مانع فعال‌سازی دیگری باشد (هر کدام پیش‌نیازهای خودش را دارد).

## انتشار مستقل

هر مخزن tag و Release خودش را دارد. نسخهٔ پنل با نسخهٔ باشگاه برابر نمی‌شود؛ تغییر پنل نیازی به نصب مجدد باشگاه ندارد. هر ZIP فقط پوشهٔ افزونهٔ مربوط را دارد و SHA-256 آن کنار release قرار می‌گیرد. فایل‌های محلی، بکاپ، کوکی، اطلاعات مشتری و ابزارهای دسترسی به سایت وارد GitHub یا ZIP نمی‌شوند.

بستهٔ پنل: `git archive --format=zip --prefix=riffside-account/ -o riffside-account-VERSION.zip TAG`.

انتشار پایدار پس از بررسی تغییرات و عبور CI انجام شود. نسخهٔ آزمایشی با برچسب prerelease مشخص شود. برای بازگشت، ZIP قبلی همان افزونه را نصب کنید؛ تنظیمات و اطلاعات کسب‌وکار را حذف نکنید. تحویل خودکار آپدیت خصوصی پروژهٔ جداست و فعلاً ادعای پشتیبانی ندارد.
